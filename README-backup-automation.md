# قدم ۱۷ — خودکارسازی Backup (تکمیل فاز ۵)

## چی ساخته شد

`.github/workflows/scheduled-backup.yml` — یک workflow که هر روز (پیش‌فرض
ساعت ۰۲:۳۰ به وقت تهران) خودکار:
۱. با حساب مدیر مدرسه وارد می‌شه
۲. `GET /api/admin/backup` رو صدا می‌زنه
۳. نتیجه رو به‌عنوان یک Artifact (فایل قابل‌دانلود) در GitHub ذخیره می‌کنه
۴. خارج می‌شه (نشست رو باطل می‌کنه)

یک دکمه‌ی «Run workflow» هم برای اجرای دستی فوری داره (زیر تب Actions در
گیت‌هاب).

## راه‌اندازی (فقط یک‌بار، حدود ۵ دقیقه)

۱. این پوشه (`madrese/`) رو در یک ریپازیتوری **خصوصی (Private)** گیت‌هاب
   قرار بدید. **حتماً Private باشه** — چون Secretهای زیر به یک حساب واقعی
   مدرسه دسترسی می‌دن.
۲. برید به Settings این ریپازیتوری → Secrets and variables → Actions → New
   repository secret، و این ۴ مورد رو اضافه کنید:

| نام Secret | مقدار |
|---|---|
| `MADRESE_BASE_URL` | آدرس سایت شما، مثلاً `https://madrese.pages.dev` (بدون `/` در انتها) |
| `MADRESE_SCHOOL_ID` | شناسه‌ی عددی مدرسه‌تون |
| `MADRESE_ADMIN_USERNAME` | نام کاربری یک حساب مدیر |
| `MADRESE_ADMIN_PASSWORD` | رمز عبور همون حساب |

۳. همین — از فردا شب خودکار اجرا می‌شه. برای تست فوری، بدون صبر کردن تا
   شب، برید تب **Actions** → workflow «پشتیبان‌گیری خودکار مدرسه» →
   **Run workflow**.

## یک نکته‌ی امنیتی مهم که باید بدونید

فعلاً **هیچ حساب «فقط برای پشتیبان‌گیری» با دسترسی محدود** در سیستم وجود
نداره — یعنی مجبورید رمز عبور واقعیِ یکی از حساب‌های مدیر رو در Secrets
گیت‌هاب بذارید. این یعنی هر کسی که به تنظیمات این ریپازیتوری دسترسی
Admin داشته باشه (نه فقط شما)، می‌تونه از این Secret برای ورود به‌عنوان
مدیر مدرسه استفاده کنه.

**توصیه:**
- این ریپازیتوری رو فقط برای خودتون نگه دارید (Private + بدون Collaborator غیرضروری)
- اگه بعداً می‌خواید یک حساب «فقط-خواندنی/فقط-پشتیبان‌گیری» جدا بسازید که
  دسترسی کمتری داشته باشه، باید یک نقش (role) و permission جدید
  (مثلاً `backup.export` به‌جای گرفتن از نقش کامل admin) اضافه کنیم — این
  خارج از قدم فعلیه، ولی اگه بخواید یک قدم کوچیک جداست.

## چطور نتیجه رو ببینم؟

تب **Actions** → روی هر اجرا کلیک کنید → پایین صفحه بخش **Artifacts** →
فایل JSON رو دانلود کنید. هر artifact بعد از ۳۰ روز خودکار پاک می‌شه (قابل
تغییر در همون فایل workflow، `retention-days`).

## اگه backup به هر دلیلی fail بشه چی؟

GitHub خودش، بدون نیاز به هیچ تنظیم اضافه‌ای، وقتی یک workflow زمان‌بندی‌شده
چند بار پشت‌سرهم fail بشه، **یک ایمیل خودکار به صاحب ریپازیتوری می‌فرسته**.
یعنی همین یک فایل هم عملاً یک لایه‌ی هشدار مجانی اضافه‌ست، شبیه همون
health-check قدم ۱۵.
